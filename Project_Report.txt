# Intelligent Feedback Analysis System (SmartFeedback) - Project Report

## 1. Introduction
The Intelligent Feedback Analysis System, also known as "SmartFeedback," is a web-based application designed to analyze, detect, and synthesize textual feedback. It acts as a comprehensive "Enterprise Feedback Intelligence" dashboard. The main goal of the project is to process user reviews or comments and determine their sentiment (positive, negative, or neutral), detect whether the text was written by a human or generated by Artificial Intelligence (AI), and extract key phrases from the text. Additionally, it offers a "Feedback Architect" feature to generate synthetic feedback data for testing or simulation purposes.

This project is beginner-friendly in its architecture but uses powerful natural language processing (NLP) techniques, making it an excellent example of full-stack AI/ML integration.

---

## 2. Core Features (What it does)

### A. Feedback Analysis (Analyze Telemetry)
*   **Sentiment Analysis**: When a user inputs text, the system evaluates the emotional tone of the feedback. It scores the text and categorizes it as Positive, Negative, or Neutral.
*   **AI Detection (Origin Analysis)**: The system analyzes the text to determine its origin. It looks at factors like vocabulary diversity, sentence length consistency, repetition, formality, and punctuation regularity. Based on these, it classifies the text as "Human", "Possibly AI", or "Likely AI".
*   **Keyword Extraction**: The system pulls out the most important words or phrases (keywords) from the feedback, summarizing the main topics discussed.

### B. Feedback Generation (Synthesize / Feedback Architect)
*   **Synthetic Data Creation**: Users can generate fake, structured feedback based on specific domains (like Hotel, College, App, Product, Restaurant, Service) and moods (Positive, Negative, Neutral, Mixed).
*   **Template-Based NLP**: It uses predefined, high-quality rule-based templates to construct realistic-sounding feedback.

### C. Insights & Dashboard (Overview)
*   **Visual Analytics**: The dashboard displays visual charts (Pie Charts and Bar Charts) showing the overall sentiment distribution of all analyzed feedback.
*   **Aggregated Stats**: It calculates the total number of feedback entries processing, average sentiment scores, and the top keywords used across all data.

### D. History Log (Archive)
*   **Data Storage**: All analyzed feedback is saved locally, allowing users to review past analyses, complete with timestamps and detailed scores.

## 3. Technology Stack (What was used to build it)

The project follows a classic Client-Server architecture, utilizing modern web technologies for the frontend and Python for the backend processing.

### Backend (Server-Side)
*   **Programming Language**: Python
*   **Web Framework**: Flask (A lightweight Web Server Gateway Interface web application framework. It routes the incoming web requests to the correct Python functions).
*   **Libraries/Dependencies**:
    *   `flask-cors`: Handles Cross-Origin Resource Sharing (allows the frontend to talk to the backend).
    *   `vaderSentiment`: A lexicon and rule-based sentiment analysis tool specifically attuned to sentiments expressed in social media and short texts. It powers the sentiment scoring.
    *   `scikit-learn`: A machine learning library for Python. While the current AI detection uses heuristics (rules), this library is included for potential model expansion (like TF-IDF keyword extraction or advanced classification).
    *   Standard Python libraries: `json` (for local database storage), `re` (regular expressions for text parsing), `math`, `os`.

### Frontend (Client-Side)
*   **Structure**: HTML5
*   **Styling**:
    *   **Tailwind CSS**: A utility-first CSS framework used via CDN for rapid UI development, creating a modern, sleek, "dark mode" aesthetic.
    *   Custom CSS (`style.css` / inline styles): Used for specific animations, glow effects (glassmorphism), and custom scrollbars.
*   **Interactivity**: Vanilla JavaScript (ES6+). It handles tab switching, DOM manipulation, and making asynchronous API calls (`fetch`) to the Flask backend without reloading the page.
*   **Charts**: Chart.js (used to render the interactive pie and bar charts on the dashboard).
*   **Icons**: Lucide Icons (for clean, modern SVG iconography).

### Database / Storage
*   **Local JSON File (`data.json`)**: Instead of a complex SQL database, the project uses a simple JSON file to store the history of analyzed feedback. This makes the project extremely portable and easy to run without database setup.

---

## 4. Project File Structure (How it's organized)

*   `app.py`: The main entryway to the application. It initializes the Flask server, defines the API endpoints (Routes like `/analyze`, `/generate`, `/stats`), handles data saving/loading to `data.json`, and serves the frontend.
*   `sentiment.py`: Contains the logic for analyzing emotions using `vaderSentiment` and extracting keywords.
*   `ai_detector.py`: Contains the heuristic algorithms (rules) that calculate vocabulary diversity, sentence consistency, and formality to detect AI-generated text.
*   `chatbot.py`: Contains the templates and logic to generate synthetic feedback based on domains and tones.
*   `summarizer.py`: Aggregates the data from all historical feedback to generate statistics for the dashboard.
*   `data.json`: The local flat-file database where history is stored.
*   `requirements.txt`: A list of all Python dependencies required to run the backend.
*   `templates/` folder:
    *   `index.html`: The main user interface file containing the structure of the dashboard.
*   `static/` folder:
    *   `script.js`: The frontend JavaScript that powers the user clicks, animations, and API communication.
    *   `style.css`: Extra CSS for animations and visual flair.

---

## 5. How It Works (The Data Flow)

1.  **User Input**: The user types text into the "Analyze" tab on the frontend.
2.  **API Call**: The JavaScript in `script.js` takes that text and sends it to the Flask server (`app.py`) via a POST request to the `/analyze` route.
3.  **Processing**:
    *   `app.py` receives the text.
    *   It sends the text to `sentiment.py` to get the emotional score.
    *   It sends the text to `ai_detector.py` to get the human vs. AI probability.
4.  **Storage**: `app.py` bundles the results with a timestamp and saves it to `data.json`.
5.  **Response**: The server sends the combined results back to the frontend as a JSON package.
6.  **Display**: The JavaScript unpacks the results and dynamically updates the HTML to show the sentiment label, the AI confidence bars, and the keywords.

## Summary for Beginners
Think of this project as a smart reader. You hand it a paragraph, and it uses Python math and rules (the brain) to tell you if the paragraph is happy or sad, and if it looks like a robot wrote it. It then draws pretty pictures (charts) on a website (the face) to show you a summary of everything it has ever read.
